# Private validation records

Run `New-ModValidationRecord.ps1 -ProfilePath <absolute-private-profile.json>` with PowerShell 7.2 or later. Copy `ValidationRecord.profile.example.json` outside the checkout and replace every placeholder and pin. All profiles and generated reports are private; they may contain local paths, descriptions and copied evidence. Nothing is redacted or uploaded.

The helper reads only explicit pinned artifacts and reports. It writes a unique run beneath an external output root, refusing overlap with source, live game data, Steam/game locations, declared roots and explicit inputs. It does not execute other helpers, load game assemblies, install files, control processes or publish.

Supported machine evidence is `Baseline` (`StardeusBaseline`, schema 1) and `Versions` (`ModVersionConsistency`, schema 1). Use the producer's context ID and SHA-256 of the exact report. Current reports must meet `NotBeforeUtc`, match subject context and bind declared artifacts. Current version evidence must include a checked root `ModInfo.json` input whose pinned `Id` matches the subject; a version number alone cannot identify the mod. `ExactPathAndHash` binds both path and bytes; explicitly selected `HashOnly` allows identical bytes at another path and requires a nonempty `Reason`. Every present file footprint in current machine evidence is rehashed, including selected game/reference inputs beyond the chosen artifact bindings; changed inputs reject the evidence. Missing selections remain report gaps and must remain absent while assembling current evidence. This covers only producer-selected files, not complete installation state. All pins are uppercase SHA-256. Required current machine evidence needs at least one artifact key. Only declared files are covered.

`Attachment` records pinned bytes without interpreting any stage. Native `release.json`, installation plans/journals and arbitrary logs are attachments: their presence never marks package, installation, startup or gameplay checks passed. Do not use unsupported Cosmoteer evidence types. Historical evidence is retained but never elevates a current stage.

A failed or unresolved machine report can be accepted as evidence while leaving its stage open. Contradictory success claims are rejected. Source review, build, startup, gameplay, save/reload, user acceptance and publication are attributed manual stages, with `Pending`, `NotApplicable`, `ReportedPassed` or `ReportedFailed` status. Reported outcomes require current accepted evidence, exact artifact bindings, reporter, explicit-offset timestamp and source note. User acceptance requires a user reporter. These are caller claims, not independently verified results or authorization. Every declared payload artifact must be bound.

The output includes `validation.json`, `validation.md`, `summary.json` and optionally copied evidence. Default behavior retains reports then fails for rejected evidence or changed/unavailable artifacts. `-RequireComplete` additionally fails for open required stages; `-ReportOnly` suppresses those final gate failures. Invalid profiles fail before output. `Recorded` describes a scoped evidence record, not overall compatibility or release approval. Evidence inputs and matched artifacts are rehashed before writing, but this is not an atomic installation snapshot.
