# Quest Request Preview

Quest Request Preview adds an explicit neutral exit to Stardeus quest and
mission offers. Players can inspect an offer and close the UI without accepting
or rejecting it.

## Release status

Version 1.0.2 is the current public release. Its feature set is intentionally
complete; future updates are expected to be limited to bug fixes and
compatibility maintenance.

### 1.0.2

- Stopped adding a neutral Close action to one-shot personal favors from ship
  Beings because Core provides no way to reopen those unanswered event quests.
- Uses Core's `ColonistQuestProvider` type to cover the complete personal-favor
  category without maintaining a fragile quest-name list.
- Runtime-validated the corrected personal-favor behavior while preserving the
  existing Signal, NPC-ship, available-quest, and Quest Hub behavior.

### 1.0.1

- Fixed undecided Signal offers being removed when a save was loaded.
- Preserved the complete Signal request through Core's existing quest save
  data without accepting or activating it.
- Added best-effort recovery for Signals saved by the earlier build before
  their undecided request data was persisted.
- Runtime-validated Signal restoration, neutral preview behavior, and a clean
  save-and-exit cycle on Stardeus 0.15.0.

### 1.0.0

- Initial public release with neutral Close, header-close, and Escape behavior
  for incoming requests, plus neutral Close actions for available and Quest Hub
  offers.

## Behavior

- Incoming quest popup:
  - Supported persistent or reopenable offers receive the mod's preview UI.
  - `Accept` retains its vanilla behavior on those supported offers.
  - `Close`, the popup close control, and Escape dispose only the popup and do
    not change `QuestState`.
  - An undecided Signal offer is registered in Core's existing serialized quest
    collection, allowing the complete offer to survive save/load while its state
    remains `Undefined`.
  - Signal quests receive an explicit red `Reject` button because Core normally
    attaches their rejection to the popup close callback.
- One-shot personal favors:
  - Requests generated by a ship Being's colonist story event retain Core's
    original quest preview and do not receive the mod's neutral Close action.
  - Core marks those story events Ending and hides their log entry before the
    preview opens, leaving no persistent entry point for reopening an unanswered
    request. Adding Close would therefore imply behavior the game cannot honor.
- Available quests and Quest Hub offers:
  - The details footer gains a neutral `Close` button.
  - Existing Accept, Reject, Remove, and Abandon actions are unchanged.

The mod has no settings, custom save schema, tick work, automation, or
dependency on another mod. Signal persistence reuses Core's existing quest save
data rather than adding a mod-owned save format.

## Public source

The Workshop package intentionally includes the complete C# source, assembly
metadata, project file, and Visual Studio solution used to build the distributed
DLL. They are included so players and other modders can inspect the behavior,
verify the patch boundaries, and reproduce the build without relying on a
closed-source binary.

## Compatibility boundary

Version 1.0.2 patches these private Core methods:

- `Game.Systems.UIUX.QuestsHandler.ShowNewQuest(Quest)`
- `Game.Systems.UIUX.QuestsWidget.LoadQuestFooter(Lifetime, WBase, Quest)`
- `Game.Systems.Quests.QuestSys.RemoveOrphanedSignalOffers()`

The Quests-window patch also uses Harmony field injection for these private
`QuestsWidget` fields so it can reuse Core's own footer lifetime and Quest Hub
context without performing reflection every time a quest is opened:

- `footLife`
- `ctx`

The incoming-popup patch intentionally mirrors the current Stardeus 0.15.0
method so it can preserve the vanilla Accept path while changing only close and
explicit rejection presentation. A Core update that changes either method or
field must be reviewed before declaring compatibility.

## Build

Open `QuestRequestPreview.sln` or build `mod.csproj` in Release configuration.
The resulting
`QuestRequestPreview.dll` is written to `Libraries/`.

The project defaults to the author's current Stardeus installation. If Stardeus
is installed elsewhere, supply the game's `Stardeus_Data/Managed` directory as
an MSBuild property:

```powershell
dotnet build .\QuestRequestPreview.sln -c Release -p:StardeusManagedPath="C:\path\to\Stardeus_Data\Managed"
```

## Runtime validation

A full Stardeus restart is required after replacing the DLL.

1. Open an incoming NPC quest request, close it, reopen it, and verify the same
   quest remains undecided.
2. Repeat with Escape.
3. Accept an incoming NPC quest and verify the normal quest activation and NPC
   behavior still occur.
4. Open an available main quest in the Quests window, use Close, reopen it, and
   verify it remains Available.
5. Accept and reject available main quests and verify both vanilla actions still
   work.
6. Open a Signal quest, close it and verify it remains undecided; then reopen it
   and confirm the same request and reward are shown.
7. Save and fully reload the game, respond to that Signal again, and confirm the
   same undecided request remains available.
8. Accept the restored Signal offer and confirm it activates exactly once.
9. Repeat with another restored Signal and use the explicit Reject action.
10. Respond to a personal favor from a ship Being and confirm its quest preview
    retains Core's original controls without a mod-added Close button.
11. Check a fresh `Player.log` for Harmony patch failures, exceptions, missing
   prefabs, or Quest Request Preview errors.
