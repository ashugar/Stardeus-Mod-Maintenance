# Intelligent Recycling read-only API

Intelligent Recycling 1.3.3 exposes contract version 1 at:

```csharp
Game.Systems.IntelligentRecycling.IntelligentRecyclingApi
```

The API lets another mod inspect Intelligent Recycling's current policy and
runtime state without changing settings, creating or cancelling goals, writing
logs, or manipulating the interface. Every returned DTO is an immutable
snapshot: public properties have getters only, constructors are not public,
and collection values are read-only copies.

## Compatibility and threading

- Check `IntelligentRecyclingApi.ContractVersion` and the flags returned by
  `GetApiInfo().Capabilities` before depending on a capability.
- Call state and object queries on Stardeus's main simulation thread. Off-thread
  calls fail closed without logging or mutating the game.
- `GetApiInfo()` remains useful before a game is loaded. Its availability flags
  and `UnavailableReason` describe the current lifecycle state.
- Treat an unavailable API, a failed `TryGet...` call, or `Unknown` ownership as
  no permission to haul. This keeps optional consumers safe across load and
  unload boundaries.
- Snapshots do not update in place. Query again when `DataRevision` changes or
  when the consumer needs current object state.

## Entry points

```csharp
public static int ContractVersion { get; }
public static IntelligentRecyclingApiInfo GetApiInfo();
public static IntelligentRecyclingStateSnapshot GetStateSnapshot();
public static bool TryGetObjectSnapshot(
    uint objectId,
    out IntelligentRecyclingObjectSnapshot snapshot);
public static bool TryGetBeingSnapshot(
    uint beingId,
    out IntelligentRecyclingSpecialTargetSnapshot snapshot);
public static IReadOnlyList<IntelligentRecyclingCategorySnapshot> GetCategories();
public static IReadOnlyList<IntelligentRecyclingProcessorSnapshot> GetProcessors();
public static IReadOnlyList<IntelligentRecyclingTrackedTaskSnapshot> GetTrackedTasks();
public static IReadOnlyList<IntelligentRecyclingSpecialTargetSnapshot> GetSpecialTargets();
```

`GetStateSnapshot()` is the comprehensive inspection surface. It contains:

- current settings and their defaults/effective state;
- dynamically discovered body-part and equipment categories;
- every compatible processor, each IR-managed family threshold, and the
  effective biological/robotic threshold currently backed by a constructed
  processor;
- scan scheduling, split scan results, and accumulated per-feature totals;
- active tasks created and tracked by Intelligent Recycling;
- Hullpiercer, Storage Capsule, Safe Box, Artillery Fungus, Dead Crawler,
  Stasis Pod, Breach Capsule Port, and lost Shuttle pad state;
- panel, top-bar widget, and managed-shortcut status.

Consumers making a decision for one object should prefer
`TryGetObjectSnapshot`. It avoids constructing the comprehensive catalogs.

### Managed processor thresholds

Version 1.2.0 adds two saved, player-configurable thresholds without changing
the contract-1 ownership rule:

- `Biological` is shared with every Nutrient Extractor.
- `Robotic` is shared with every Disassembler and applies to robotic parts and
  equipment.

`StateSnapshot.ProcessorFamilies` exposes the saved IR value through the
additive properties `ManagedThresholdAvailable` and `ManagedThreshold`.
`EffectiveThresholdAvailable` remains false until at least one compatible
constructed processor exists; a saved managed threshold by itself does not
authorize recycling or external hauling. When a processor is available,
`EffectiveThreshold` reports the constructed-family value used for ownership.

Threshold synchronization is bidirectional. A change in Intelligent Recycling
updates every processor in that family; a processor-side change updates the
saved Intelligent Recycling value and every peer. New processors inherit the
managed value when construction completes. On migration from 1.1.1 or earlier,
the managed value is seeded from the highest constructed processor threshold,
preserving the effective cutoff already used by that save.

## Authoritative object ownership

For normal supported quality-bearing targets, Intelligent Recycling owns the
object when:

```text
quality <= effective compatible processor threshold
```

Only this condition releases it to external hauling:

```text
quality > effective compatible processor threshold
```

Equality is deliberately not released. When the master switch, parent setting,
category setting, or compatible processor is unavailable, ownership is
`Unknown`; that is not permission for another automation mod to claim the
object.

Permanent mind protection is reported as `PermanentlyProtected`. Unsupported or
non-quality-bearing objects are `NotManaged`, but
`ReleasedForAutoHauling` remains false because the API makes no positive claim
about their safety for a particular consumer.

Explicit special targets are reserved for Intelligent Recycling even while
their toggle is disabled, their processor is unavailable, or their safety
condition is not ready. This prevents generic hauling from undermining the
special cleanup workflow.

Lost Shuttle pads are constructed tiles rather than loose objects, so they do
not participate in `TryGetObjectSnapshot` ownership decisions. Consumers can
inspect them through `GetSpecialTargets()`. Active replacement workflows are
also represented by `GetTrackedTasks()` with the additive `LostShuttle`
tracked-target kind; phases without a current Core goal use goal ID `0` and an
inactive goal snapshot. `ActiveLostShuttleReplacements` is the authoritative
count of workflows still being reconciled.

## Policy ownership versus transient blockers

`Ownership` and `ReleasedForAutoHauling` answer who owns the policy decision.
`CanCurrentlyBeHauled` additionally applies momentary game-state blockers.

For example, a loose supported item strictly above the threshold can report:

```text
Ownership = ReleasedForExternalHauling
ReleasedForAutoHauling = true
Forbidden = true
CanCurrentlyBeHauled = false
```

Forbidden state, an existing goal, an assigned worker, or a reservation does not
rewrite the policy owner. It only prevents action right now. Stored, carried,
inactive, and in-device objects can retain an informative policy classification,
but are not reported as released while they are not loose active objects.

The automation scan uses the same transient-queue gate. A reservation therefore
prevents Intelligent Recycling from replacing a Store goal or requesting
Disposal, and the last-scan count is exposed as `Scan.Reserved`.

Non-finite object quality or applicable processor-threshold data fails closed.
The object reports `QualityRelation=NotApplicable`, the `Invalid` blocker,
`Ownership=Unknown`, `DecisionReason=InvalidObject`,
`ReleasedForAutoHauling=false`, and `CanCurrentlyBeHauled=false`. A constructed
processor with a non-finite threshold remains identifiable as a compatible
processor, but it does not provide an effective threshold. Normal property and
configuration-copy changes are intercepted by Intelligent Recycling and
normalized back to the finite saved family threshold; this fail-closed state
also protects against unsupported direct state mutation.

## Recommended Auto Hauling gate

After Auto Hauling has applied its own vanilla storage and object-safety checks,
its Intelligent Recycling compatibility gate should be fail-closed:

```csharp
if (!IntelligentRecyclingApi.TryGetObjectSnapshot(objectId, out var ir)) {
    return false;
}

if (!ir.ReleasedForAutoHauling || !ir.CanCurrentlyBeHauled) {
    return false;
}

// Continue with Auto Hauling's own policy and vanilla TryOrderStoring path.
```

Do not reproduce threshold comparisons, category discovery, Brain/Core or mind
protection, special-target detection, or processor selection in the consumer.
Those rules belong to Intelligent Recycling and may evolve behind the versioned
contract.

If Intelligent Recycling is optional rather than a declared hard dependency,
the consumer should discover and call the API reflectively and use the same
fail-closed result when the assembly, contract, capability, or query is
unavailable. A compile-time reference must use `Private="False"`; never copy or
bundle `IntelligentRecycling.dll` inside another mod.

## Revisions and contract evolution

`DataRevision` is process-local and monotonic for the lifetime of the loaded mod
assembly. It advances for Intelligent Recycling lifecycle transitions, settings
and category changes, shortcut-state changes, scan requests and completed scans,
statistics resets, and tracked-task reconciliation. It is not saved as a game
value and should only be compared with a prior value from the same running
process.

Per-object lifecycle and blocker fields are evaluated when
`TryGetObjectSnapshot` is called. A consumer making an action decision should
therefore query the object at that decision point rather than assuming an older
snapshot is still current.

New informational DTO properties, enum values, and capability flags may be
added without changing contract version 1. Consumers must ignore values they do
not recognize. A semantic break or incompatible signature change requires a new
contract version. The API never removes safety by treating an unknown value as
permission to haul.
